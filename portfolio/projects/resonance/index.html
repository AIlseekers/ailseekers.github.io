01

项目概览

常规笔记工具按时间或文件夹组织内容，天然适合检索，天然不适合发现。Resonance 换了个起点：先决定节点是什么、边有哪些类型，再让内容长进这张图里。

02

设计要点

为什么用图库

「这个判断最早出现在哪篇笔记里」「哪两个观点的前提其实是冲突的」——这类问题在关系型库里要写多层 JOIN，在图里是一次路径查询。

代价

图模型对写入一致性和前端渲染都不友好。节点一旦多起来，一次性渲染整张图会直接卡死，必须按需展开并做视口裁剪。

03

技术路线

  1. 原始笔记与引用
  2. 抽取实体与关系
  3. 写入 Neo4j（节点 / 边类型约束）
  4. React 端按视口请求子图
  5. 局部展开与路径高亮
04

我的职责

  • 定义节点与边的数据模型，划清「内容」与「关系」的存放边界
  • React 端图渲染与交互：按需加载子图、避免全图重绘
  • 前后端衔接：把图查询结果整理成渲染层能直接消费的结构
