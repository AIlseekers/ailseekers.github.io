01

项目概览

CalmMind AI 面向欧美用户，做的是「有人陪着呼吸」这件事：用户说出当下的状态，系统据此生成一段引导，节奏、语气和时长都要跟着人走，而不是播放一段固定的音频。

产品链路被拆成两段：前端负责体验与身份，后端负责编排与生成。这条边界不是架构洁癖，而是为了让模型与会话逻辑可以独立迭代，不被界面改动牵制。

02

背景与约束

核心问题

冥想是低强度、长停留的场景，用户对「被打断」极其敏感。一次错误的加载态、一次重复的鉴权跳转，都会直接摧毁沉浸感。同时生成内容必须稳定，不能每次开场都换一套说法。

解决方案

前端把认证做成状态而非页面跳转，登录态在客户端统一收口；会话由 LangGraph 的状态机组织，明确区分「开场—引导—收束」三段，模型只负责段内文本，不负责流程判断。

03

技术路线

  1. 用户输入当下状态
  2. Clerk 提供身份与登录态
  3. 前端按状态渲染，不刷新页面
  4. FastAPI 校验 JWT
  5. LangGraph 推进会话状态机
  6. DeepSeek 生成段内文本
  7. 流式返回并落库 Supabase
04

我的贡献

  • 确定 Frontend-only 边界：只改前端，不触碰数据库与后端结构，为后端 JWT 验证预留接口
  • 完成 Clerk 注册、登录与用户状态的集成方案设计
  • 搭建 Next.js 16 + React 19 + Tailwind 4 + TypeScript 的前端骨架与设计系统
  • 统一模型接入层，全部生成请求走 DeepSeek 的 OpenAI 兼容接口，便于替换与降级
05

当前状态
