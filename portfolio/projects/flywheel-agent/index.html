01

项目概览

投放运营的真实成本不在创意，而在每天都要重复的那几十个动作：拉报表、看哪一环掉了、想几条标题、检查有没有违规词、排发布时间、回评论。这个项目把这些动作拆成可编排的步骤，交给智能体按计划执行。

02

系统构成

  • 运行层：Bun + Next.js，本地开发固定端口与 webpack 编译模式，避免热更新与接口调试互相干扰
  • 能力层：12 个能力域技能包，覆盖数据采集、漏斗诊断、内容生成、合规校验、发布排期等
  • 接口层：46 个平台接口，报表、查询、账户管理三类 scope 已打通
  • 调度层：4 条定时任务——08:00 投放数据同步 / 09:00 文案草稿 / 20:00 互动草稿 / 周日 21:00 发布日历
03

评论意图分类

评论是转化路径上信息密度最高的一段。系统把每条评论归入 7 类意图，其中价格询问、购买意向与效果质疑需要不同的回复策略，而怀疑类评论必须转人工。

7 类意图

ASK_PRICE 问价 / PURCHASE_INTENT 购买意向 / ASK_EFFECT 问效果 / ASK_PRINCIPLE 问原理 / SHARE 用户分享 / DOUBT 质疑 / SUPPORT 售后支持

分流规则

DOUBT 类自动置 need_human=true 转人工；ASK_EFFECT 与 ASK_PRINCIPLE 使用限定话术库，不自由生成，避免在效果描述上越界。

04

合规约束

  • 禁用绝对化用语（治愈、根治、最有效等），命中即整条退回重写
  • 生成前先注入产品事实边界：无教学服务、无线下门店，不得暗示疗效
  • 每条产出保留「生成 → 审核 → 发布」三段记录，出问题可回溯到具体一次生成
05

我的职责

  • 设计整体架构与能力域划分，把运营经验沉淀成可复用的技能包
  • 打通投放数据链路，落地近 7 天数据自动监控与漏斗环节自动录入
  • 建立评论意图分类体系与人工接管规则
  • 配置 4 条定时自动化，验证端到端可跑通后再交接
